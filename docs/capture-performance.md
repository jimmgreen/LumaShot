# 截图启动与控件框选（2026-09-16）

## 行为与资源

- 快捷键后保留原有鼠标形状、热点和位置采样，在后台抓屏的同时枚举窗口并启动控件识别；截图显示不等待控件识别。
- 隐藏窗口的图形设备与表面准备提前，与后台抓屏并行；只有冻结图像上传和首帧绘制成功后才显示，避免把等待转移到用户开始框选之后。
- 抓屏像素复制和不透明 alpha 设置合并为一次遍历。显示器图像使用原图行跨度直接上传，避免临时 Crop；单块 3840×2160 屏幕减少约 31.6 MiB 的临时 CPU 像素缓冲。
- 包含光标时仅合成光标与截图相交的小块，避免为光标另建整帧 DIB 和来回复制整帧；关闭包含光标时不复制鼠标图标资源。
- 背景模糊用滑动窗口累加，保留两次整数取整和边界采样，逐像素输出不变。
- 同一会话的多个覆盖窗口共用 D3D 设备；关闭最后一个覆盖窗口后释放设备、交换链和截图，没有跨会话设备保留或持续抓屏/绘制。
- 最后一个表面关闭时清理 Direct2D 资源并调用 DXGI Trim。文字绘制按线程复用一个 16 MiB 字形缓存上限的 CPU Context，避免反复销毁已使用 Context 后的内存增长；缓存不保存截图或绘制目标。未改动 LumaText 二进制或其他项目。
- 控件识别助手按次启动，使用低于正常的优先级，600 毫秒等待上限。先识别原生子窗口，再读取 UI Automation 的控件边界、类型和可见状态；不读取文字、值、标题或截图像素。共享缓冲上限为 32 个顶层窗口、1024 个区域，UI Automation 最多探测 8 个可见根窗口。
- 选择最上层命中窗口中的较小控件；隐藏、过小、越界或几何已变化的区域不参与框选。结果晚到时只更新尚未选定的悬停范围，不替换已完成或正在拖动的选区。取消递增会话编号，丢弃旧结果并结束助手。

## 验证方式

`lumashot_startup_render_perf_test` 用旧模糊算法作参考，覆盖小尺寸、非整倍数尺寸、负原点、随机像素和 1080p/4K；另外读回合成 WIC 图像验证带行跨度的区域上传，并用隐藏窗口验证多窗口设备共享与释放。

`lumashot_capture_latency_test` 用自建不透明窗口覆盖每块显示器，走正式 `WM_HOTKEY`、后台抓屏、覆盖窗口显示路径；记录第一次及重复启动时间、进程内存和空闲 CPU，验证首帧拖动、按钮框选、结果晚到和关闭释放。它不保存屏幕图像、不读取用户偏好或剪贴板。耗时包含测试消息调度，不是鼠标到显示器的光学延迟。

`lumashot_elements_test` 使用自有按钮、编辑框、嵌套面板和没有 HWND 的 UI Automation 虚拟按钮，检查隐藏控件、遮挡、取消、慢提供程序和助手缺失降级。

## 本机实测结果

3840×2160、60 Hz，自建不透明画面覆盖实际显示器，经正式快捷键处理和真实 BitBlt 抓屏验证。不包含个人图片、偏好或剪贴板；隔离环境拒绝桌面抓屏时，在允许桌面访问的测试环境完成同一套验证。

| 项目 | 最终结果 |
| --- | --- |
| 首次快捷键到可操作 | 276.7 ms |
| 后续五次 | 173.1 / 167.0 / 155.0 / 181.9 / 154.5 ms |
| 六次截图关闭后的专用内存 | 41.9 / 42.6 / 42.0 / 43.4 / 42.9 / 42.3 MiB |
| 最后一次关闭后的工作集 | 68.6 MiB |
| 最后一次空闲 CPU | 313 ms 观察窗口内累计 CPU 时间为 0 ms |
| 图像/区域释放、首次拖动、控件框选、准备阶段取消 | 全部通过 |

第一轮已减少 CPU 复制、但仍串行创建图形资源的版本，首次约 525 ms、重复约 250–283 ms；对应原始记录为 `capture-overlap-before.csv`。最终记录为 `capture-performance-trace.csv` 和 `capture-performance-latency.txt`。这些是本机短期测量，不是所有设备的延迟承诺。

独立文本实验连续 12 轮：修复前带文字 Paint 的专用内存从 39.6 增至 250.2 MiB，修复后为 39.6 至 40.5 MiB；WIC Demo 从 39.2 至 266.1 MiB 的增长，降为 38.8 至 42.4 MiB。图形设备与无文字绘制的对照保持稳定。内存回归检查要求首轮之后的专用内存增长不超过 16 MiB。

光标小块合成以旧算法的独立 `CopyIcon` 快照作逐像素参考，覆盖七类光标、每类 25 个位置。系统共享光标与快照的半透明通道可能有一级差异，因此不混用两者作为参考。背景模糊逐像素相同，4K 独立测量约 35.5 ms 降至 12.8 ms。

## 已知边界

自绘应用未公开的控件、跨权限访问受限的窗口，以及在预算内未完成的识别会退回整窗框选；仍可手动拖选。没有使用 OCR 推测视觉区域。真实多显示器混合 DPI、HDR 与各种第三方应用控件树仍需对应硬件和应用验证。首帧仍需完成抓屏、上传和绘制，不能承诺所有硬件上零延迟。

UI Automation 的线程隔离、缓存和超时遵循微软文档：[线程注意事项](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-threading)、[缓存属性](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-cachingforclients)、[调用超时](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomation2-put_transactiontimeout)。
