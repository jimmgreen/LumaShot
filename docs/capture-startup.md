# 截图启动与放大镜跟随修正（2026-09-15）

## 复现与证据

用户指出：截图刚出现时，放大镜尚未跟随鼠标，立即框选会卡；随后确认我们打开的合成测试窗口里，持续移动放大镜也不跟手。

新增 `lumashot_startup_test`，使用合成图片铺满实际显示器，通过正式 Application / Renderer 创建覆盖窗口。测试在 WM_SHOWWINDOW 后立刻投递四次鼠标移动、按下、40 次拖动和释放，不等待预热，也不先用同步消息等待初始化结束。不读取个人图片、设置或剪贴板。

本机 3840×2160、60 Hz、6 个逻辑处理器。修改前，首次投递的移动等待约 266 ms，四次悬停处理后都有尚未完成的重绘；日志显示可见窗口内发生了约 235 ms 的绘图初始化。窗口先显示、后初始化整屏位图的时序问题已复现。

仅修正启动并没有解决全部问题。用户实际移动鼠标的那次记录有 99 次移动，处理耗时 P95 151.59 ms。绘制命令 P95 仅 0.44 ms，但整屏 EndDraw 提交中位 105.42 ms、P95 145.81 ms。阻塞发生在整屏提交；尚未确定显卡、驱动或桌面合成内部为何出现该等待。这一记录来自用户实际操作，不是自动投递输入。

## 修改

- 隐藏窗口期间完成每块屏幕的渲染目标、位图上传和首次绘制，再显示覆盖窗口。
- 准备后重新读取鼠标位置，避免首帧放大镜使用准备前的旧坐标。截图所保存的鼠标采样不受影响。
- 新增独立的 122×122 像素放大镜窗口，使用冻结图像生成 20×20 像素区域的六倍最近邻放大、蓝色边框和十字线。
- 同一个高亮窗口内移动鼠标，只更新小窗口的位置和图像，不再提交相同的整屏 Direct2D 画面；高亮窗口改变才重绘整屏。
- 放大镜透明命中、不激活、不夺取点击；按下框选立即隐藏，取消时释放。约 58 KiB 图像缓冲连续复用，没有空闲刷新循环。
- 放大镜使用物理像素坐标，处理负坐标与边缘取样；界面小窗口不写入复制、保存或 OCR 图像。
- 隐藏准备失败时取消该次会话，释放窗口，允许下一次截图重试。
- 原截图到贴图测试改为等窗口可见再发送输入，避免向尚未显示的窗口发送手势。

## 验证范围

`build.bat` 通过，13 项 CTest 全部通过，见 `magnifier-test-results.txt`。

- 初始四次悬停和 40 次立即拖动均完成重绘；初始化发生在隐藏阶段；放大镜实际窗口位置随输入变化，按下即隐藏。
- 连续 120 次移动：整屏绘制 3 次（含启动），独立放大镜更新 121 次（含初始显示）。投递输入至更新完成 P95 **0.9606 ms**，最大 **10.5192 ms**（首个事件）；放大镜更新本身 P95 **0.6949 ms**。
- 负坐标映射、六倍像素块、边框与十字线、右下角限位、极小源图不越界、鼠标穿透样式、隐藏/重现和关闭释放均通过。
- 已检查由生产像素函数生成的合成放大镜图片。移除了此前通过 GDI DC 读取 Direct2D 窗口的未经验证的像素判据，最终自动测试中没有该读屏调用。

## 验证边界

自动投递输入耗时不是鼠标到显示器的光学延迟。此前已有“自动测试很快、用户实际操作很慢”的差异，因此新合成数字不能代替人工确认。最终独立放大镜版本尚待用户真实屏幕体验验证。打开前的初始化时间仍存在；改变高亮窗口、拖动选框仍需整屏绘制。

此前电脑操作工具无法定位覆盖窗口，并在用户按 Esc 后停止，未继续使用该工具。

原始记录：`capture-startup-before.csv`、`capture-startup-after.csv`、`magnifier-real-before.csv`、`magnifier-synthetic-after.csv`。正式包默认不记录；需要继续定位时，可在程序旁放置 `diagnostics.enabled`，取消截图会写出纯数字 `interaction-trace.csv`，不保存截图、文本或剪贴板。
