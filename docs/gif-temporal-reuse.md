# GIF 帧间近似复用

用户授权保持原尺寸/帧率、允许轻微损失，并将实测有效的优化加入默认导出流程。

## 实现

GifFrames 提供内部 colorTolerance 参数，默认为 0（精确复用）；应用 GIF 导出使用 8。预计算调色板颜色对的兼容表，当前像素与上一个实际保留的像素每个 RGB 通道均相差不超过 8 时，复用该像素。此后沿用重复帧合并、透明差分及现有 gifsicle 候选选择。

比较对象是保留/待显示的画布，而不是上一张未经处理的输入帧。因此缓慢渐变超过阈值后会更新，不会因相邻源帧变化很小而无限累积误差。高对比文字变化照常更新。阈值限制是相对于量化后的输入；原视频量化和后续可选 `--lossy=10` 另有误差，不宣称总误差均小于 8。

不改变 GifOptions、尺寸、选定帧率、时长、循环或录制编码，不新增 UI 设置。

## 授权样本对比

原 GIF：1678×938，168 帧，11200 ms，3424462 字节。仅在本地构建目录分析；没有把用户内容加入回归测试素材或源文件。

| 方案 | 字节 | 时间加权 RGB MSE | 最大单通道差 |
|---|---:|---:|---:|
| 无损 O3 | 3424462 | 0 | 0 |
| 128 色 + O3 | 3365446 | 0.629 | 33 |
| 96 色 + O3 | 3267565 | 7.700 | 58 |
| 64 色 + O3 | 2994021 | 32.980 | 83 |
| 帧间容差 8 + 无损 O3 | 2883519 | 2.303 | 8 |

采用最后一项：节省 15.8%，约 3.27 MiB → 2.75 MiB。168 帧和全部显示时间保留。每帧解码后按时间线比较，抽查文字/字幕关键帧。样本压缩版未追加有损 LZW，因此实测通道上限 8 可直接核对；原始 GIF 保留。

`--lossy=20/40` 的整段试验分别超过 45 秒中止，未采用这些不完整结果，也未提高应用的 30 秒候选超时。样本只有约 162 种实际颜色，192 色压缩未改变体积。测试效果取决于内容，不保证每段录屏都有同样节省。

## 验证

- gif_pipeline 增加缓慢渐变、误差不累积、显著文字变化即时更新、重复帧合并和时长保持的合成用例。
- 既有精确模式的逐像素差分、长延时、透明和进程回退测试继续保留。
- gif_quality 与非对齐尺寸 recording_geometry 继续验证真实 MP4→GIF 导出。
- 历史工具 `lumashot_gif_candidate_benchmark` 已在项目精简时移除：仅用于旧版有损容差研究，不属于当前默认的无损导出流程。帧间复用的功能回归仍由 `tests/gif_pipeline_test.cpp` 覆盖，现行导出性能比较使用 `tests/gif_export_benchmark.cpp`。
- 生产 GifFrames 生成的样本中间文件与实验版本 SHA-256 相同，确认使用同一算法。默认应用从原始视频量化后应用此步骤，并非重压用户 GIF。

最终构建通过（C++20 /W4 /WX）；6/6 测试通过，总计 85.49 秒，日志见 gif-temporal-tests.txt。
