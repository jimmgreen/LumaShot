# 实机截图交互诊断（2026-09-15）

## 已确认的观察

用户报告此前发布的 `LumaShot-smooth-selection` 在真实截图操作中卡顿，而诊断程序顺滑。因此，之前 1080p 单帧基准不能证明用户问题已解决。

本轮未继续修改刷新算法。新增可选的内存耗时记录，用同一套 Application / Renderer 分别对比合成画面、真实截图的独立诊断入口、正式程序入口。用户亲自操作，画面没有保存或作为自动测试素材。

| 路径 | 配置 | 用户反馈 |
|---|---|---|
| 合成诊断 | 实际显示器尺寸，3840×2160 | 顺滑 |
| 真实截图独立诊断 | 真实捕获，默认配置，无托盘快捷键注册 | 顺滑 |
| 正式程序诊断 | 真实捕获，正常用户设置、托盘及快捷键路径 | 顺滑 |
| 同一正式程序关闭记录后重启 | 同一个二进制、同一目录，取消诊断开关 | 仍然顺滑 |

正式入口记录的显示模式为 3840×2160、60 Hz；优先级 Normal，6 个逻辑处理器均可用。框选 180 次绘制的 P95 为 11.064 ms，最大 14.077 ms；这不等于鼠标到屏幕的实际延迟。首次显示与位图初始化单列统计，不能混作热拖动速度。

目前没有捕获到用户所述的卡顿状态，因此根因尚未证实。同一二进制关闭记录后用户确认仍然顺滑，说明这份程序的顺滑表现不依赖诊断记录。不能把“加入诊断之后顺滑”当作因果关系，也不能把偶发 EndDraw 慢帧直接当作本次根因。

## 诊断实现

- 正式程序所在目录存在 `diagnostics.enabled` 时，启动时启用记录；取消截图时写 `interaction-trace.csv`。
- 无该开关时不记录。相同二进制可在相同目录对照，避免切换程序路径这一变量。
- 日志仅包含阶段耗时、消息年龄、屏幕尺寸和少量运行配置，不包含图片、文字、窗口标题、保存目录或剪贴板。
- 分别记录绘制命令和 EndDraw，首次位图初始化、捕获及模糊、窗口显示单独记录。
- 自动测试驱动的同步 SendMessage 时间不代表真实鼠标输入延迟；本轮实机日志来自用户操作。
- 原始证据：diagnostic-synthetic-before.csv、diagnostic-real-before.csv、diagnostic-production.csv。
- 使用 `scripts/summarize-interaction.ps1 -Path <csv>` 汇总。首次未进入稳定状态的慢帧仍保留在原始日志。

最近一次发布的优化结论应以本记录中的实机观察及限制为准；不宣称已定位根因。
