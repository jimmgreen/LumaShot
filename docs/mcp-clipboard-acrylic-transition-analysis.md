# 剪贴板展开材质切换分析

日期：2026-09-22。本轮仅静态检查与方案建议，未修改生产代码，未进行运行时视觉验证。

## 已确认的代码行为

- src/clipboard/panel.cpp 的 LiquidBackdrop 在液态模式关闭 DWM backdrop，并切换非客户区、边框和圆角策略。
- MotionTick 在展开 elapsed >= 350ms 时调用 LiquidBackdrop(false)，随后用 70ms 将外壳不透明度从 0.96 过渡到 PanelOpacity。
- src/ui/acrylic.h 的 PanelOpacity 为深色 0.72、浅色 0.60。
- 因此展开包含明确的材质切换，而不只是形状变化。DWM 自身的实际合成时序仍需运行时录制确认，不能仅凭静态代码认定具体驱动延迟。

## 建议

首选低风险方案：把贴边、细颈、脱离回弹保留在折叠条，将展开面板恢复为独立的常规原生 Acrylic 窗口；展开只做轻量位移或显隐，不再让同一 HWND 在异形模式与原生 backdrop 间反复切换。提前配置 backdrop 可减少切换来源，但隐藏窗口首次显示仍需实测，不保证完全消除系统材质过渡。

若必须保留完整展开形变且以稳定观感为第一优先，可统一折叠、动画和展开的自绘不透明主题材质，移除最终恢复 Acrylic 的步骤。这保留几何液态效果，但不再提供真实桌面模糊。

若完整形变与真实实时模糊都必须保留，需要另行验证可对背景采样及模糊结果进行任意形状裁剪的合成方案；不能仅凭普通 DirectComposition visual 裁剪推断系统 HWND backdrop 同样会被裁剪。该路径属于架构性研发。

不建议只延长现有 70ms 淡化、增加等待或无条件调用 DwmFlush：它们不能消除两种材质之间的视觉差异，且不构成 backdrop 就绪保证。

## 后续验收

用自有合成背景录制首次展开、连续展开收起、快速反向、深浅主题、透明效果关闭、混合 DPI 和失焦情况，确认无矩形漏底、材质突变、输入焦点变化及空闲持续渲染。具体实现路线待用户选择。
