# 剪贴板展开面板：更低宽度下限与尺寸持久化

## 范围和实现

用户要求降低展开面板的最小宽度，让用户自己调整并持久化。本次仅修改 LumaShot 的剪贴板几何、窄屏布局和相关测试，不修改兄弟 Pulse。

- 最小宽度从 400 DIP 降为 280 DIP；默认宽度仍为 400 DIP，不强制覆盖现有用户尺寸。最小高度保留 480 DIP。
- `src/clipboard/layout.h` 提供共用尺寸边界；窗口拖拽约束和 INI 恢复校验使用同一最小宽度，避免拖窄后重启被判为无效。
- `src/clipboard/panel.cpp` 在实际缩放结束时将物理像素换算为 DIP，调用既有原子保存逻辑；折叠后的移动保留展开尺寸。重新创建面板或进程重启时恢复保存的尺寸。
- 正常配置仍使用 `%LOCALAPPDATA%/LumaShot/clipboard-layout.ini`，仅存放面板位置与尺寸。本次没有读取或改写用户实际配置文件或剪贴板历史。
- 测试模式只在明确传入隔离配置路径时进行布局读写；不自动解析个人目录，不启用真实剪贴板监听、历史存储或全局快捷键。
- 窄布局按可用宽度分配五个分类按钮，保留所有卡片操作的 32 DIP 点击区域。缩小图片/文件预览占用的高度，给时间与操作留出独立底栏。
- 小于 368 DIP 时隐藏非必要的顶栏快捷键文字，快捷键功能不变；时间和底部提示使用单行省略，防止越界与重叠。默认宽度下保留原布局。

## 验证

- 修改前，新增策略回归 29 项检查中 10 项失败，复现原 400 DIP 限制与窄尺寸读回被拒绝。
- 修改后 `clipboard_width`：3141 项检查、0 失败。覆盖 280/320/400/560 DIP、100%/125%/150%/200% DPI、深浅主题，共 32 组渲染与几何组合，以及 native resize、折叠拖动、重新启用、新面板对象和独立进程恢复。
- 扩展现有 `clipboard_header_drag` 的宽度矩阵：2283 项检查、0 失败。保留头部拖动、交互控件、边角缩放、固定面板不抢焦点等检查。
- 一次早期策略复核出现 INI 写入/读回失败；增加失败诊断后未再复现。随后 20 个独立进程的策略检查均通过，并完成上述两组完整定向检查。首轮失败日志保留，未修改保存函数来掩盖错误，也未放宽断言；偶发写入失败的根因尚未确定。
- 已人工查看 280 DIP / 150% 浅色、280 DIP / 200% 深色及原 400 DIP / 100% 的生产代码渲染图，未见所查看界面的文字或按钮重叠。图片全部来自合成记录。
- `/W4 /WX` 构建通过；本轮未运行无关历史测试套件。不同 DPI 在测试中受控模拟，不等同于完整真实多显示器交互验收。
- 原 GIF 录制源码及录制 worker 哈希保持不变，保留上一轮解除 GIF 限时的修改。
