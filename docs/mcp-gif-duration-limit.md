# GIF 固定时长限制解除

## 用户要求与改动

用户明确要求放开一分钟限制。GIF 与视频现在都不设置人为录制时长上限，停止由用户决定；没有换成更大的隐藏上限，也没有新增必须开启的设置。

- `src/recording/worker.cpp`：将实际录制入口使用的参数集中到 `Ui::CaptureOptions()`，GIF 与视频都传入 `duration_limit=0`。
- 移除 UI 的 60 秒兜底停止条件，并移除专为该条件存在的 2 号定时器及其清理代码。计时显示继续由录制线程的状态消息驱动；倒计时、预览播放和通知定时器保留。
- 未修改 `src/recording/core.cpp` 的磁盘空间检查、编码器错误处理、暂停/恢复和取消逻辑。引擎的显式限时参数仍可供内部调用使用，但应用不会对 GIF 设置它。
- 同步 `README.md`、`docs/recording-design.md` 与 `docs/recording-implementation.md`，去掉当前行为中的固定时长说明。

## 原因回顾

修改前，GIF 入口传入 600000000 个 100 ns 时间单位，即 60 秒；录制线程据此限制帧数，UI 定时器也在达到 60 秒后调用 Stop。初版设计中的默认限时被写成了常量，并非 GIF 格式的全片时长限制。

## 实际验证结果

- 已添加使用生产 UI 参数构造的回归用例。保留原行为时，GIF 不限时断言失败，视频不限时及原始参数断言通过；不是把编译失败当作回归复现。
- 新增 CTest `gif_duration`：使用合成画面实际编码跨过 65 秒，覆盖暂停/恢复、旧定时消息不终止录制、用户停止、成品媒体时长、完整 GIF 导出、独立解码与导出中取消保留旧目标。
- 测试仅使用合成纹理和 build/ 下的隔离文件，不录制个人桌面、声音或剪贴板。测试中的 90 秒合成帧数和超时是测试看门狗，不是应用上限。
- 修复后构建通过，`/W4 /WX` 保持开启；不限时参数回归由失败变为通过。
- `gif_duration` 实际录制 65.8666 秒、988 帧、0 丢帧，旧的 60 秒定时消息没有终止录制，最后由用户停止动作收尾。导出的 GIF 经独立解码为 66 秒、330 帧，并通过中途取消保留既有目标文件的检查。
- `recording_ui` 与 `gif_pipeline` 通过。人工查看生产绘制代码输出的 `build/gif-duration-test-output/3156/after-one-minute.png`，状态条显示 `01:05`，时间和控件没有重叠或截断。
- 原有独立 `media_recording` 在原夹具目录首次运行触发 60 秒测试超时；同一个未重新编译的测试程序、同样 60 秒超时，在新的隔离目录复测以 5.15 秒通过。其录制核心与 GIF 转换源码哈希未变。首轮超时根因未确定，保留原始日志，没有删测、弱化断言或放宽超时，不能宣称首轮整组全绿。
- 未运行完整历史测试套件，也没有做个人桌面实录、超长时长或所有显卡组合的验证；65 秒是本次验证长度，不是新的应用上限。
