# LumaShot 代码审查：性能与默认对话框

**日期：2026-09-18｜性质：审查，不是修复交付**

## 结论

本轮发现 **3 项应优先修复的问题**：

1. 文字编辑重绘复制整个 `Document`，连同撤销/重做历史一起深拷贝。
2. 大面积模糊马赛克在 UI 绘制线程同步重算；缓存命中后仍重复创建并上传位图。
3. 贴图保存结果遍历期间弹出模态错误框，消息重入可能使 `saves_` 迭代器失效。

另有 6 项中优先级问题、1 项低优先级问题，以及完整的默认对话框清单。性能优化应先处理数据复制、模糊计算和绘制调度，**不建议先重写编码器或取消画质校验**。

扫描覆盖 `src` 下 126 个第一方 C++ 头/源文件的风险 API；深入审读了截图、标注、绘制、贴图、录制/导出、OCR 服务、设置及消息框关键路径。不是对全部代码逐行验证，也不包含第三方依赖内部审计。

**本轮没有修改 `src/`、`tests/`、构建配置或安装包。** 仅增加报告及 `build/review-performance-dialogs/` 下的合成探针、日志。没有使用个人截图、首选项或剪贴板作为测试输入。

## 证据等级与优先级

- **实测**：用当前已构建的项目库执行组件级合成探针，两次独立运行均完成。
- **静态确认**：代码和调用链确认存在该操作；实际耗时或故障触发率未测。
- **风险推导**：存在明确的可达事件顺序，但本轮未做动态故障注入。
- **P1**：应优先修复的交互瓶颈或稳定性风险；**P2**：随后处理；**P3**：低成本改进或需要进一步定量的优化。

以下位置均指本轮审查的源码快照，版本记录见 `build/review-performance-dialogs/source-versions.json`。

## 一、按优先级排列的发现

### R1 · P1｜文字重绘与导出复制了不需要的完整历史

**位置**：`src/app/application.cpp:860–868, 810–814`；`src/model/document.h:82–98`；`src/model/document.cpp:64–78`。

- 编辑已有文字或序号说明时，`WM_PAINT` 为了隐藏旧文字，执行 `editing = app->document_`。
- `Document` 没有自定义轻量复制语义，默认复制会深拷贝 `marks`、`undo_`、`redo_`，包括各标注的笔迹点数组和字符串。
- 普通截图导出也先复制 `document_`，再按值捕获进工作线程；后台编码并不能消除**提交任务前**发生在 UI 线程的复制。
- 历史上限是 100 条，不是字节预算。复杂笔迹越多，文字编辑、导出入口越容易出现明显停顿，多显示器绘制还可能重复承担同一复制成本。

**实测**：24 个标注、每个 5,000 个点、100 个历史快照，单次完整副本的中位耗时为 **88.77 / 89.79 ms**；仅复制当前 `marks` 为 **0.044 / 0.072 ms**。这里是组件微基准，不是实际窗口帧耗时。

**建议**：绘制器接收“暂时隐藏的标注索引/说明文字覆盖”而不是复制文档；导出只构造当前标注快照并移动捕获。后续再考虑不可变共享笔迹、差量撤销和历史字节预算，不要直接改变全局 `Document` 复制语义以免破坏撤销。

**验收**：长笔迹和 100 条历史下，文字编辑不复制历史；导出提交时间不随历史条数线性增加；单次手势撤销、拾色器取消、序号文字编辑保持现有语义。

### R2 · P1｜大面积模糊马赛克同步占用 UI 线程

**位置**：`src/ui/render.cpp:156–168, 326–340`；`src/model/mosaic.cpp:8–38, 42–92`。

- `MarkShape` 在绘制期间直接调用 `BuildMosaicBlur`。拖动、改变强度或增加笔刷点会使完整标注缓存比较失败，重新处理整个受影响区域。
- 虽然滑动盒式滤波本身已是线性复杂度，但后续遮罩仍通过 `BuildMosaicTiles` 建立 4px 网格、哈希去重、排序并计算均色；模糊遮罩使用的是覆盖范围，均色计算在这里没有被使用。
- 即便 CPU 缓存命中，模糊分支仍每次调用 `Bitmap(cache.blur)`，重新创建/上传 D2D 位图。CPU 缓存不等于 GPU 资源缓存。

**实测**：合成矩形、`mosaic_cell=64`，仅 `BuildMosaicBlur` 的中位耗时：640×360 为 **10.30–13.05 ms**，1280×720 约 **50.9 ms**，1920×1080 为 **125.51–135.41 ms**。未包含上传、文字、其他标注及窗口呈现。

**建议**：缓存目标相关的 GPU 位图；将覆盖计算与颜色统计拆开；矩形遮罩走直接填充路径。交互重算采用后台生成＋版本丢弃，或低成本预览、松手后生成最终结果；笔刷尽量按新增区域更新。必须验证最终像素及隐私遮挡效果，不能只降低模糊质量换速度。

**验收**：缓存命中时没有重复位图上传；大范围拖动与强度调整保持输入响应；取消/切换文档后旧后台结果不能覆盖新状态。

### R3 · P1｜贴图导出错误弹窗存在容器迭代器重入失效风险

**位置**：`src/pin/pin.cpp:193–216`；`src/pin/pin.h:40–43`；`src/app/application.cpp:158`。

`Saved()` 遍历 `std::vector<std::future<SaveResult>>`，擦除当前结果后仍保留迭代器，并在循环内调用 `MessageBoxW`。与此同时，完成通知以及 100ms 定时器都能再次调用 `Saved()`。

**可达顺序**：先提交慢任务 A，再提交快速失败的 B；外层遍历跳过 A，在处理 B 时弹窗；弹窗的嵌套消息循环中 A 完成，内层 `Saved()` 擦除 A。外层恢复后，之前的迭代器已经失效，可能访问已移除的 `future` 或触发异常。

**证据等级：风险推导。** 本轮未动态复现崩溃，不能把它称为已观察到的用户故障。

**建议**：先将完成结果取出到局部队列并结束容器遍历，再更新 UI/展示通知；必要时增加重入保护和延迟通知。**只换成现有自绘消息框并不能解决此问题**：`src/ui/themed_message.h:110` 同样运行嵌套消息循环。

**验收**：至少两个任务乱序完成、一个失败并保持错误框打开；后续任务仍可完成，关闭窗口也不会触发无效迭代器、重复消费或错误的 busy 状态。

### R4 · P2｜选区确认后的无变化鼠标移动仍触发全视图重绘

**位置**：`src/app/application.cpp:513–566, 389, 222–234`；`src/ui/render.cpp:173–176, 254–268`。

- “选区未确认且选区未变”的路径有早退；确认选区后，即使没有拖动、悬停控件没变，也会执行 `Invalidate()`。
- `Invalidate()` 标记所有 overlay；绘制时逐个提交全部标注，而非只提交变化或可见的标注。
- 贴图编辑模式下，每次失效还会重新建立 HRGN 并调用 `SetWindowRgn(..., TRUE)`，即使区域完全没变。
- 滑块和选区拖动中的 `UpdateWindow` 会同步进入绘制，减少消息合并空间。

**证据等级：静态确认，未测实际 WM_PAINT 频率。** 系统合并消息和帧就绪检查会限制实际呈现次数，因此不能把鼠标轮询率直接当作重绘帧率。

**建议**：比较悬停值和视觉状态，只在需要时失效；马赛克光标等确实随鼠标变化的工具单独处理。缓存窗口区域，按脏区/相关显示器更新，并结合现有帧就绪机制合并绘制请求。

### R5 · P2｜已有字形缓存，但每次绘制仍重建布局、路径和部分样式资源

**位置**：`src/ui/text_renderer.cpp:20–58`；`src/ui/render.cpp:33–43, 108–144, 173–176`；`src/model/tag_appearance.h:22–54`。

- 现有 LumaText 上下文及 16MiB CPU 缓存、字体格式缓存是有效优化；不能说项目“完全没有文字缓存”。
- 但每次 `TextRenderer::Draw` 仍创建 `IDWriteTextLayout`、LumaText renderer 和 frame；静态标签、工具栏文字与未变更的标注也重复经过该流程。
- 画笔/箭头每次绘制会重建路径及部分 stroke style；标签自适应色也重复采样与对比度搜索。

**实测补充**：混合明暗背景的 `ResolveTagColors` 单标签约 **0.057–0.059 ms**，远低于前两项，不应优先于文档复制和模糊计算。

**建议**：按文本/字体/尺寸/换行等布局依赖建立有容量上限的布局缓存；平移不必重新排版。静态路径和样式按标注版本缓存；目标丢失时清理目标相关资源。不要改成无界缓存，也不要让缓存持有整张截图或过期 render target。

### R6 · P2｜400ms 防抖之后仍在 UI 线程同步落盘配置

**位置**：`src/app/application.cpp:161, 734–745, 391, 805–806`；`src/app/preferences.cpp:50–79`。

`WM_TIMER` 直接调用 `FlushProperties()` → `preferences_.Save()`。写入包含复制旧文件、多次 INI 写入、缓存刷新及 `MOVEFILE_WRITE_THROUGH`；退出截图也会同步 flush。

**影响**：防抖减少了次数，却没有消除单次磁盘阻塞。慢磁盘、重定向配置目录或杀毒扫描下可能表现为停止调色后短暂停顿。未实测这些环境下的延迟。

**建议**：单写入者后台队列，合并最新不可变配置快照，保留原子提交；避免旧快照晚完成而覆盖新配置，也要协调独立设置进程的写入。

### R7 · P2｜进入贴图标注仍同步执行图像处理链

**位置**：`src/pin/pin.cpp:238–245`；`src/pin/selection_tools.cpp:78–85`；`src/app/application.cpp:210–218`；`src/pin/annotation.cpp:5–15`。

点击贴图标注或按空格后，UI 线程直接执行 `FlattenTextMarks`、`PinAnnotationPreview` 和 `BlurBackdrop`，然后创建/展示绘图视图。没有文本装饰时 `FlattenTextMarks` 的按值返回仍复制图像；预览还按整个监视器工作区分配画布。

**影响**：高分辨率贴图进入编辑时可能出现卡顿，路径与普通截图的后台采集/模糊处理不一致。这里的 `BlurBackdrop` 与 R2 的 `BuildMosaicBlur` 是不同函数，不能套用 R2 的耗时数字。

**建议**：让贴图进入标注也采用后台准备＋generation 校验，再在 UI 线程提交窗口资源；准备期间用可取消的忙碌状态避免重复进入。

### R8 · P2｜停止录制预览时同步 join，取消不保证立即返回

**位置**：`src/recording/worker.cpp:99–108, 124–126, 203`；`src/recording/preview.cpp:9, 22–29`。

`StopPreview()` 在 UI 调用路径上执行 `request_stop()` 后立刻 `join()`。后台有停止检查和 30 秒循环截止时间，但 `MFCreateSourceReaderFromURL`、seek、`ReadSample` 本身是同步调用，截止时间不能中断正阻塞的 API。

**影响**：预览正在加载时重录/关闭，可能等待解码或 I/O 返回。没有证据表明正常文件一定会卡住；这是取消延迟边界的风险。

**建议**：取消请求与 UI 状态切换分离，使用可管理生命周期的完成消息/任务对象；需要硬超时保障时隔离到可终止的工作进程。不要简单 `detach` 捕获 `this` 的线程。

### R9 · P3｜MP4 进度文件反复从头读取

**位置**：`src/recording/mp4_export.cpp:68–82`；`src/recording/mp4_export.h:17`。

每隔约 250ms 重新打开不断增长的 `progress.txt` 并读取全部行。导出越长，重复解析的历史越多；累计工作随记录增长呈二次趋势。单次外部工具已有 15 分钟超时，因此并非无限增长，实际占比尚未测量。

**建议**：保存读取偏移、只消费新增完整行，正确处理每次尝试重建文件。此项优先级低，不应据此删除逐帧质量验证。

### R10 · P2｜三处保存对话框把系统错误当成用户取消

**位置**：`src/app/application.cpp:800–806`；`src/pin/pin.cpp:180–183`；`src/recording/worker.cpp:171`。

三处 `GetSaveFileNameW` 返回 FALSE 后直接返回，未调用 `CommDlgExtendedError()`。用户取消与对话框初始化/资源等失败被混为一谈，表现可能是“点击保存没有结果”。

**建议**：统一保存对话框封装，返回成功/取消/失败三态；`CommDlgExtendedError()==0` 才按取消处理，其他错误进入统一提示与诊断。若迁移 `IFileSaveDialog`，也要区分取消 HRESULT 和真实错误。

## 二、默认对话框与默认菜单完整清单

### 直接调用系统消息框：6 处

| 位置 | 触发场景 | 建议 |
|---|---|---|
| `src/app/application.cpp:74` | `Application::Notice`：快捷键冲突、采集/复制异常、部分录制启动失败，以及文字输入空间不足等 | 正常业务提示统一到消息服务，区分信息/警告/错误，不要所有错误都用信息图标 |
| `src/pin/pin.cpp:212` | 贴图导出失败 | 先解决 R3，再统一提示外观 |
| `src/pin/pin.cpp:213` | 贴图结果发布到剪贴板失败 | 同上 |
| `src/pin/pin.cpp:302` | 贴图文字工具窗口异常 | 先退出危险回调/绘制状态，再延迟展示 |
| `src/pin/pin.cpp:374` | 贴图窗口消息处理异常 | 同上 |
| `src/app/main.cpp:39` | 程序顶层异常，`MessageBoxA` | 建议保留不依赖渲染器的原生兜底；可统一 Unicode 转换，不宜无条件依赖自绘消息框 |

`Notice` 的调用扩散位置包括 `application.cpp:110,155,175,318,334,909`，以及 `text_edit.cpp:65`。因此一个入口统一后能覆盖多条业务路径。

### 原生保存文件对话框：3 处

| 位置 | 用途 |
|---|---|
| `src/app/application.cpp:800–804` | 截图 PNG 保存 |
| `src/pin/pin.cpp:180–182` | 贴图 PNG 保存 |
| `src/recording/worker.cpp:171` | MP4 / GIF 保存 |

三者使用 `GetSaveFileNameW`，覆盖确认由 `OFN_OVERWRITEPROMPT` 触发，仍是系统 UI。**原生文件选择器不等于错误实现**：建议优先封装、统一所有者/默认目录/错误处理；如采用 `IFileSaveDialog`，它仍然是系统外观，并不会自动变成项目自绘主题。完全自绘文件选择器成本高，且需承担键盘、无障碍、路径与 Shell 功能维护，不建议只为配色而重写。

### 默认菜单：1 处，不是对话框

`src/app/application.cpp:179–188`：托盘菜单使用 `CreatePopupMenu` / `TrackPopupMenu`，未走项目自绘菜单。如追求严格的全局主题一致性，可单独纳入后续 UI 统一计划。

### 不应误报的地方

- **设置窗口**：`settings_dialog.cpp:249` 使用 `DialogBoxParamW`，但 `resources.rc:7–32` 是无标题栏、owner-draw 控件资源，窗口又执行自绘和无边框配置；不能仅因 API 名称就认定它是漏改的默认对话框。
- **已有自绘消息框**：`src/ui/themed_message.h:95–113`；录制导出错误、重录/关闭确认、部分启动失败已使用它，截图和贴图则尚未统一。
- **原生 EDIT**：承载输入、IME、选区等能力，不等于默认弹窗；不应为了“全自绘”破坏现有输入法行为。
- 本次 `src` 检索未发现 `TaskDialog*`、`GetOpenFileName*`、`ChooseColor*`、`ChooseFont*`、`SHBrowseForFolder*` 的业务调用。未把第三方库或 Inno Setup 安装界面的系统 UI 算入上述数量。

## 三、合成探针结果与边界

使用独立控制台探针，MSVC x64 `/O2 /MT`，链接当前构建的项目库；未启动截图 UI 或真实录屏。每项先预热一次，Document 测量 8 次（取排序后的上中位样本）、模糊测量 5 次取中位数；整个探针独立执行两轮。

| 组件与输入 | 第 1 轮 | 第 2 轮 |
|---|---:|---:|
| Document：无历史，24×5,000 点，完整复制 | 0.5342 ms | 0.7177 ms |
| Document：20 条历史，完整复制 | 14.4408 ms | 15.2248 ms |
| Document：100 条历史，完整复制 | 88.7722 ms | 89.7943 ms |
| 同一 100 条历史文档：仅复制当前 marks | 0.0440 ms | 0.0723 ms |
| 模糊 640×360，半径参数 64 | 10.3020 ms | 13.0456 ms |
| 模糊 1280×720，半径参数 64 | 50.9111 ms | 50.9839 ms |
| 模糊 1920×1080，半径参数 64 | 125.5111 ms | 135.4120 ms |
| 混合背景标签自适应色，平均每标签 | 0.0588 ms | 0.0568 ms |

当前点数据为 960,000 字节；100 个等量历史快照加当前内容，仅点数组载荷就是约 97 MB（十进制），还未计入对象、字符串和分配器开销。

**限制**：顺序微基准受分配器、冷热缓存和机器负载影响；完整副本测量包含局部副本销毁。不能把比值直接解释成产品整体提速倍数，也不能用这些数值替代 ETW/UI 延迟测试。本轮没有测真实显示器重绘率、网络目录配置保存延迟，也未做模态重入故障注入。

证据：`build/review-performance-dialogs/probe.cpp`、`run-probe.bat`、`probe.log`、`probe-repeat.log`、`source-versions.json`。

## 四、已经做对、应保留的设计

- 普通截图采集/背景模糊以及 PNG 合成/编码在工作线程；UI 以结果消息和 generation 检查接收结果。
- `Application::WaitForWork` 与帧就绪事件配合，没有常驻空转渲染循环。R4 是鼠标活动期间的冗余工作，不是空闲 CPU 忙等。
- OCR 采用独立进程和共享映射，元素扫描在后台且有超时；不应把这些后台等待误报为 UI 阻塞。
- 录制 GPU 转换、受限表面池、过期帧跳过和异步导出已有基础保障。
- MP4 的多轮压缩、时间戳/AAC 检查和整段 SSIM 是“体积优先且保持质量”的策略成本；不要通过移除守护条件制造表面上的提速。
- 保存使用临时文件与原子替换，取消不应损坏用户已有文件；性能修改必须继续保持这一点。

## 五、建议实施顺序

1. **第一批**：R3 消息重入稳定性 → R1 去除重绘/导出历史复制 → R2 模糊缓存和交互计算迁移。
2. **第二批**：R4 失效调度/区域缓存、R7 贴图后台准备、R6 配置异步提交、R8 预览取消生命周期。
3. **第三批**：R5 有界布局/路径缓存、R9 增量读取进度；统一五处正常业务原生消息框，保留顶层原生兜底；将三处保存对话框封装并解决 R10。

每批单独做针对性验证，保留连续绘制、即时属性、拾色器取消、组合标注联动、DPI 和单次手势撤销语义。**本轮只是审查，不重打包安装包；后续实际修改应用时，再按既定要求提供新的测试安装包和 SHA256。**
