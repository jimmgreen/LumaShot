# 文本与背景配色：Tag 风格调整方案（待确认）

## 本轮边界

仅调研和提出方案，不修改应用源码、不构建、不打包。核对了当前实现，并查看仓库既有的合成预览 build/palette-preview/light.png 与 build/palette-preview/dark.png；它们不是本轮新生成的截图，也不是用户当前桌面的截图。

## 参考结论

Ant Design Tag 的经典预设彩色样式是同色系的深文字、浅底、弱边框；并不是把整个标签一起降低透明度。v5.27.6 的源码把背景、边框、文字分别映射到色阶 1、3、7；inverse 才使用强色底和浅文字。当前官网也区分 filled、outlined 与 solid。经典浅底通常是一个不透明的浅色值，不应把它误说成真正透出底图的 alpha 背景。

参考：
- https://ant.design/components/tag/
- https://5x.ant.design/components/tag/
- https://raw.githubusercontent.com/ant-design/ant-design/5.27.6/components/tag/style/presetCmp.ts
- https://raw.githubusercontent.com/ant-design/ant-design/5.27.6/components/theme/util/genPresetColor.ts

本方案依据用户“背景不是实体色”的表达，推荐在 Tag 配色层级基础上采用真正的半透明色底；这是适配截图标注的方案，不宣称与 Ant Design CSS 完全相同。

## 当前实现的问题

1. src/model/annotation_palette.h 的 MixNoteColor 固定返回 alpha=FF。AnnotationTones 是把主题色与白色或 #141414 混成实色，10%/12% 是 RGB 混色比例，不是背景透明度。
2. src/ui/render.cpp 的普通文字背景直接 FillRectangle(rect)，填满文字布局框；没有 Tag 式边距、小圆角与细边框。因此短文字也可能像一条不透明底板。
3. src/model/note_color.h 返回 border，但 src/ui/number_render.cpp 的说明文字分支只填底、绘字，没有绘制该边框。
4. Renderer::Number 调用 AnnotationTones(mark.color,false)，序号/胶囊固定用浅色方案；普通文字和说明却根据底图明暗切换，既有深色预览可见不一致。
5. 自定义说明文字对比度不足时，ResolveNoteAppearance 会把配对底色往黑或白推；与“不形成实体底板”的目标冲突。
6. src/app/text_edit.cpp 的说明文字编辑面板仍可能采用界面主题底色；普通文字的预览还会再次调字色。编辑中、提交后、导出不能仅靠独立公式保持一致。

## 推荐视觉方案

目标：文字是主角，底色是轻量衬托，边界靠同色系弱描边，而非大块实底。

| 项目 | 浅底图 | 深底图 |
| --- | --- | --- |
| 文字 | 同色系深墨色，100% 不透明 | 同色系浅亮色，100% 不透明 |
| 背景 | 主题色 alpha 10%–14%，初始建议 12% | 主题色 alpha 16%–20%，初始建议 18% |
| 边框 | 同色系 alpha 24%–32% | 同色系 alpha 28%–36% |
| 外形 | 1 DIP 边框、4 DIP 小圆角 | 同左 |
| 内容边距 | 左右 6–8 DIP，上下 2–4 DIP；随后按字号和 DPI 校准 | 同左 |

以上透明度是设计起点，必须用六色、真实合成后背景和复杂底图验证后定稿，不预先声称任何背景都能达到 4.5:1。

- 不降低整体标签透明度，字始终清楚；不加渐变、阴影或磨砂。
- 保留现有六个主题色及顺序，不同时重做画笔、荧光笔和图形填充的颜色。
- 普通自动尺寸文字的底板贴合实际文字；多行文字采用一个紧凑背景框，不按每一行画独立彩条。手动调整过的文本框尊重用户设置的尺寸。
- 自动深浅配色仍依据截图局部，而不是工具栏主题。对混合/花纹背景不能只用平均亮度判断；应检查采样分布和合成后的文字对比度，先调文字明度，再在有限范围内调背景 alpha。
- 不为了满足对比度阈值默默变成不透明黑白底。复杂图片无法同时保证强透底和处处高对比时，提供明确的增强底色选项或手动浅/深方案，而不是偷偷改变风格。
- 无背景模式保留；自定义文字颜色默认不被自动配色覆盖；自动配色和精确自定义色的优先级需要清楚区分。

## 实施范围（确认后执行）

1. 新增局部的标签外观解析器，输出 ink/fillRGBA/borderRGBA/radius/padding。不要全局修改 MixNoteColor 的 alpha 行为，避免牵连现有画笔、形状、荧光笔。
2. 普通带背景文字、序号说明及自定义文本标签共享此解析器，并统一相应的深浅配色；不修改贴纸纸张底和工具栏面板背景。
3. 将绘制、测量、点击范围与文本框几何一起调整，避免增加 padding 后遮字、剪裁或选中框错位。
4. 屏幕预览、编辑状态和导出使用一致的外观规则。原生 EDIT 无法仅靠背景画刷实现真正逐像素半透明；建议保持原生输入/IME，在合成底图上提供准确预览，不对整个输入窗口做低透明度处理。
5. PNG 导出将半透明标注正确合成到截图上；不把“标签透出底图”误做成“输出图片整体透明”。明确预乘 alpha，防止边缘发灰。
6. 新样式单独持久化/版本化，保留旧白底、黑底、黄底与旧记录读取，不静默重解释历史数据。

## 验收与顺序

先提供六色静态视觉样稿：白底、深底、浅深交界和棋盘/照片纹理底。对比“经典 AntD 色阶浅底”与“推荐的真正半透明底”，让用户确认是否需要看见底图纹理。

确认后再实现，并检查：文字不褪色、底图能透出、弱描边可辨、深色标签不突兀、短文本不拖长底板、编辑/提交/导出一致；覆盖 DPI、缩放、多行、自定义色和旧配置。

本轮无应用源码改动，无构建、测试执行或安装包变更。
