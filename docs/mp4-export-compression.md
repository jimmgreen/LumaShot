# MP4 体积优先导出（2026-09-17）

按用户选择，默认使用 AV1 MP4，保持原尺寸、每帧时间戳、帧数与压缩 AAC 音轨。优先尝试 SVT-AV1 preset 6 / CRF 36 / tune 0 / lp 2 / lookahead 16；候选未通过时尝试 CRF 28，再尝试 H.264 slow / CRF 18。候选必须更小。

## 画质与时间轴检查

平均逐帧 SSIM 至少 0.99，至少 99% 的帧达到 0.98，任何一帧不得低于 0.96。该组合同时拦截整体画质下降、持续局部下降和严重坏帧，但不因极少量瞬时低点就强迫全片使用更高码率。指标比较候选与已压缩录制原文件，衡量新增损失，不是未压缩桌面画质，更不是“无损”承诺。该门槛是本轮“体积优先、允许少量画质损失”的取舍，取代原来的 0.998 / 0.99。

尺寸、帧数、逐帧呈现时间、音频包时间、音频采样率/声道及压缩音频 SHA-256 仍检查，时间容差 1 ms。编码同时指定 fps_mode passthrough 与 enc_time_base demux，避免将真实采集时间舍入到固定帧率网格。

Media Foundation 估算的平均帧率分数不是稳定的容器重封装不变量；不再对它做分数完全相等比较，而使用全部帧时间与帧数作为依据。SSIM 在相同时间基下按解码帧序号对齐，防止用相邻帧错位比较；校验日志帧数必须等于输入。

## 安全与兼容

每次导出独立临时目录，后台隐藏运行、低优先级；AV1 采用受限并行级别与 16 帧前视，单进程提交内存上限 3 GiB，每个进程最多 15 分钟。取消终止所属进程并不覆盖目标文件；成功提交后才显示完成。工具缺失、失败、超时、超限、校验失败或无法减小体积时保留原文件，并在保存提示中明确显示“未压缩”。

录制预览始终使用原始 H.264 缓存，AV1 导出不要求改变原有预览链。导出的 AV1 文件需要支持 AV1 的播放器；部分系统原生播放器可能需要解码扩展。本轮不安装扩展、不修改系统播放器。

保存成功提示显示实际使用的编码与缩小百分比。独立 FFmpeg 运行时及许可证随安装包分发，新的完整编码器运行时会增大安装包；这是应用安装体积，不是导出视频体积。

最终实测与安装包校验见本轮 docs/mcp-mp4-size-optimization.md。
