# 贴图 OCR 验证记录

日期：2026-09-15。机器：Intel Core i5-8400 @ 2.80GHz，6 个逻辑核心；Windows 11，10.0.22631。Release，C++20，MSVC /W4 /WX。OCR 使用两条 CPU 推理线程，关闭 spinning，FP32。

## 本轮优化：无标题栏与识别加速

- 贴图移除标题栏及关闭按钮，图像区域与原图同尺寸；状态移至右键菜单。
- 双击非文字空白关闭，文字双击/三击保持选词/选行。识别未完成时只允许双击局部纯色空白关闭；拖动之后不会被当成关闭双击。
- 文字标注图标改为无底部横线的明确 T。
- 检测与识别共用 CPU 内存池，按请求大小扩展；减少逐行分配开销，仍保持两条推理线程和 30 秒空闲进程退出。
- 双线性缩放共用坐标和像素读取；短文字识别最小填充宽度由 320 降至 128，不降低原图分辨率，不更换模型或量化。

| 同机对比 | 优化前 | 优化后 |
|---|---:|---:|
| 100 张合成截图 CER | 0.44%（33/7499） | 0.44%（33/7499） |
| 760×240 小图热识别 P95 | 229 ms | 171 ms（缩短约 25%） |
| 1080p 20 行热识别 P95 | 964 ms | 802 ms（缩短约 17%） |
| 64 个中英短标签，中位识别耗时，3 次 | 2623 ms | 1501 ms（缩短约 43%，文本完全一致） |
| 常规基准峰值私有内存采样 | 127 MiB | 174 MiB |
| 64 个短标签峰值私有内存采样 | 175 MiB | 213 MiB |

内存池用额外几十 MiB 换取识别速度，空闲释放机制保持不变。以上均为合成内容，本轮未把用户提供的截图或其他个人内容作为测试样本。结果依内容和机器负载而变。

原始记录：`docs/ocr-speed-before.txt`、`docs/ocr-speed-after.txt`、`docs/ocr-dense-comparison.json`。本轮 7 项回归全部通过：`docs/ocr-refinement-tests.txt`。共享绘制代码生成的贴图预览已检查，标题栏空间为零；DPI 切换、空白单击保留、空白双击关闭、文字双击/三击保留均通过验证。

## 首版实测（历史对照）

| 项目 | 结果 | 范围 |
|---|---|---|
| 识别精度 | 33 / 7499 字符错误，CER 0.44% | 100 张不同的合成截图，每张含唯一编号；16–24 px，中英混合、数字、明暗背景，Microsoft YaHei UI |
| 小图热识别 P95 | 217–228 ms | 上述 760×240 图片，不计文件读取 |
| 1080p 20 行热识别 P95 | 965–1086 ms | 两轮各 10 次；包括检测、识别、排序；一轮略超 1 秒目标 |
| 1080p 20 行冷识别 P95 | 1920 ms | 10 次新子进程，包括启动、加载模型、共享内存传递与结果解析 |
| 峰值私有内存 | 130.15 MiB | 独立基准进程每 5ms 采样；含模型、推理和合成图渲染；非精确分配器峰值 |
| 峰值工作集 | 147.50 MiB | 同一基准进程 Windows PeakWorkingSetSize |
| 便携发行包 | 约 44.58 MiB，未压缩 | 主程序、worker、CPU 运行库、模型、字典、文档与许可证 |
| 空闲释放 | 30 秒后子进程不存在 | 真正关闭进程；已识别贴图不依赖模型继续存活 |

这些结果不是所有屏幕内容的精度承诺。数据集词汇范围有限，未覆盖所有系统字体和真实应用；未把低清晰度、小字、照片背景、手写、竖排、倾斜文本的结果混入正常字号指标。热启动性能接近目标，尚不能保证所有测试轮次 P95 ≤1 秒。

## 功能与视觉验证

- CTC blank 与重复 token、非等宽字符位置、反向和跨行选字、换行、组合音标、UTF-16 代理对、IPC 截断拒绝。
- 真实 OCR 子进程和共享内存，单 worker 串行队列，重试版本隔离，取消后不接受旧结果，worker 异常退出与恢复。
- 模型缺失及损坏：使用独立合成无效模型目录验证异常返回，不修改实际模型。
- 真实贴图窗口鼠标消息、三击选行、Esc 清除选择、图像像素不被高亮改写、DPI 消息保持物理像素宽度。
- 置顶按钮与截图结束流程使用合成截图运行，不捕获个人桌面或读取个人偏好。
- 鼠标背景恢复覆盖负坐标与部分交集；OCR 图像在恢复背景后重新应用标注，马赛克不会被原图覆盖。
- 由生产绘制路径生成 `build/pin-selection-preview.png` 和 `build/pin-150dpi-preview.png` 并检查高亮及无标题栏的图像布局。预览不是桌面截图。
- 自动测试不读取个人剪贴板内容；剪贴板忙时的失败分支有错误保留逻辑，但未通过占用用户剪贴板做现场验证。

7 项完整回归全部通过，结果保存在 `docs/ocr-test-results.txt`。后续错误文本转换修复的 3 项定向复验见 `docs/ocr-final-focused-tests.txt`；便携目录中的模型与本地 C++ 运行库已通过实际识别检查，见 `docs/ocr-package-check.txt`。编译通过不能替代上述功能与视觉验证。

## 工程取舍与限制

- 原截图仍保留合成后的采样鼠标，仅额外保留鼠标下面的小块背景；准备 OCR 图像时恢复该区域。避免为 OCR 长期保留第二张完整桌面图。
- 检测采用 DB 概率图连通域、外扩、重叠切片合并；当前几何为轴对齐行框，四边形对应其四角。未实现任意倾斜透视校正。
- 字符边界来自 CTC 时间步；首尾字符覆盖行框边缘，内部按相邻发射区间划分，属于估算而非真实字形分割。
- 简单多栏按空白分割排序；含跨栏标题、复杂表格等排版可能需要手动分段复制。
- 真实混合 DPI 多显示器、HDR、极端大图资源峰值尚未完整实机验证。
- 模型和运行库固定来源、版本、校验值及许可证见 `deps/ocr/manifest.json`。模型通过镜像取得后，与官方 Hugging Face 公布的 SHA256 一致。
