# 录制界面与画面故障修复

本轮按用户要求暂停 GIF 体积优化。研究用 Gifsicle 和有序抖动代码未接入正式导出，不随常规构建运行压力测试。正式 GIF 保持原来的自适应调色板/误差扩散策略，本轮只修复共用像素读取。

- 设置和录制窗口共用 DWM 圆角策略、窗口区域裁切、背景色及透明度；录制窗口此前缺少设置窗口的 DWM 圆角属性，且背景更不透明。
- 预览和 GIF 解码使用原始媒体缓冲的 IMF2DBuffer::Lock2D 获取实际有符号行距；线性缓冲作为回退并检查长度。避免把默认行距套在有填充的二维缓冲上造成错行。
- 截图快捷键不再因录制进程存在而被拦截。准备/预览窗口允许被截图，实际录制阶段仍排除控制条。
- 框选改为离屏组合后一次提交，抑制独立背景擦除；复用离屏缓冲，预览时释放。避免先填背景再挖透明区域被分次显示。

验证：`recording_pixels` 覆盖 1918/3838/3840 × 2160 的实际二维缓冲、正负行距、逐像素比对；本机另读取自建 4K MP4 验证预览二维颜色位置。`recording_ui` 检查浅/深色与 100/125/150/200% 缩放下四角 Alpha=0、设置同等透明度、DWM 圆角属性、框选缓冲复用及透明内部。`recording_coexist` 通过真实截图热键消息打开自建示例截图，同时保持录制进程存活。设置、媒体录制及截图启动测试通过。

研究记录保留，后续优化需另行完成画质/耗时/峰值内存验证；本轮不承诺减小 GIF 文件。
