# GIF 与屏幕录制设计

状态：交互与技术设计，尚未实现。日期：2026-09-16。
用户已认可选区、悬浮录制条、预览导出的交互方向。本轮补齐设置入口与低占用架构；文中的数值是设计默认值或验收目标，不是测量结果。

## 1. 设置与入口

设置增加「常规 / GIF / 录屏」页签，保留现有磨砂材质、深浅主题与键盘操作。常规页将原截图快捷键扩展为三行：

| 动作 | 初始快捷键 | 唤起结果 |
| --- | --- | --- |
| 截图 | Ctrl+Alt+A（已有用户值保留） | 现有截图选区 |
| GIF 动图 | Ctrl+Alt+G | 选区界面，GIF 模式选中 |
| 屏幕录制 | Ctrl+Alt+R | 选区界面，录屏模式选中 |

快捷键仅打开准备界面，不能直接开始录制。托盘同步增加「录制 GIF…」「录制屏幕…」，快捷键占用时仍能进入。没有录制任务时才创建录制界面进程。

每行支持点击录入、清除为「未设置」、Esc 撤销、Tab 导航、失焦撤销。录入钩子仅在捕获组合键期间存在；排除纯修饰键、F12 与无效组合。F1–F11、F13–F24、PrtSc、Pause、ScrollLock 允许不带修饰键单独绑定（见 `src/app/hotkeys.h` 的 `StandaloneShortcutKey`/`ValidShortcut`）；字母、数字等普通键仍必须包含 Ctrl、Alt、Shift 或 Win。原因：Ctrl/Shift 组合在 CAD 等程序弹出菜单期间会被菜单模态循环吞掉，导致 RegisterHotKey 无法触发，而单独的功能键不受影响，可在菜单展开时截图。三行内部冲突即时提示「与截图快捷键重复，请更换组合键」，系统注册失败提示具体动作与组合。保存失败保留草稿，取消不写入；恢复默认仅修改当前设置草稿，不重置标注。

全局键使用 RegisterHotKey + MOD_NOREPEAT，不使用常驻低级钩子。设置进程录入期间通过有界 IPC 通知主进程暂停这三项动作的分发；录入结束、失焦、子进程退出都解除抑制。不要靠常驻轮询判断输入状态。

保存时由主进程统一验证三项注册。保留未变更绑定，释放并重绑变更项，支持互换组合；任一失败回滚本次注册并报告。Windows 注册与文件写入不能真正原子化：回滚若被外部程序抢占，必须显示实际不可用项，不能声称旧绑定完整恢复。持久化采用临时文件和替换提交，失败恢复旧运行配置；不要延续现有逐字段写入造成半保存的风险。保留未知配置项、标注属性及原截图字段。

旧配置缺少新字段时补默认值；允许关闭任一全局绑定。启动注册失败只提示相关功能不可用，不阻断其它动作、不自动弹设置。设置共享内存协议从当前 version 2 升级，增加版本、长度、动作与字段校验，父子版本不一致明确失败。

## 2. 默认参数与设置内容

| 参数 | GIF 页 | 录屏页 |
| --- | --- | --- |
| 格式 | GIF | MP4（H.264；有声音时 AAC） |
| 帧率 | 15，另选 10 / 20 / 25 | 30，另选 15 / 60 |
| 尺寸 | 输出宽度 960 px，保持比例，不放大小区域 | 默认最长边 1920 px，保持比例；可选原始尺寸 |
| 声音 | 无声音，不显示音频开关 | 系统声音默认开启，麦克风默认关闭 |
| 鼠标 | 默认包含实时鼠标 | 默认包含实时鼠标 |
| 开始倒计时 | 默认 3 秒，可关闭 | 默认 3 秒，可关闭 |
| 其它 | 默认循环；导出前可改尺寸、帧率 | 画质：标准 / 清晰，默认标准 |

这些是新功能独立参数，不改变截图的光标行为。准备工具条可临时调整，开始成功后记住有效参数；启动失败、取消草稿不覆盖已保存设置。GIF 与视频均不设人为录制时长上限，由用户手动停止后进入预览；磁盘不足、设备故障等安全条件仍可结束录制，不以固定时长代替用户决定。

## 3. 交互与状态

主路径：空闲 → 选择目标 → 准备 → 倒计时 → 录制中 ⇄ 已暂停 → 正在收尾 → 预览 → 保存/导出 → 完成。

- 选择目标：区域、窗口、单屏；GIF 与视频共用选择器。区域首版限制在一块显示器内，跨屏拖选在边界停止并提示。窗口模式跟随目标窗口，不复用当前截图的“桌面可见矩形”来假装窗口捕获。
- 准备：显示物理像素尺寸、格式与必要参数。可拖动/调整边界。倒计时前隐藏冻结的选区遮罩，让实际桌面恢复；只留下边框和控制条。录制后锁定区域及模式。
- 倒计时：只有倒计时提示，不保存帧；Esc 返回准备。设备及编码器可在点击开始后异步准备，未就绪显示「正在准备…」，不阻塞窗口。
- 录制中：控制条显示模式、红点、时长、音频状态、暂停、停止。边框无调整手柄。控制条可拖动；不增加实时缩略预览或波形。时长仅每秒重绘一次。
- 暂停：显示琥珀色状态与恢复按钮，时长冻结；关闭捕获会话并停止音频采集，保留编码器和有界资源以便恢复。暂停时间从视频和音频的统一时间轴扣除。
- 停止：停止接收新帧，处理已接受队列，后台完成封装；显示「正在完成录制…」，完成前不能打开未封装文件。
- 预览：默认暂停，用户播放时才解码；失焦/最小化暂停播放。GIF 提供首尾裁剪与时长、帧率、宽度、循环；视频首版仅预览、保存及「另存为 GIF」，不承诺视频剪辑。
- 导出：GIF 后台转换，有进度、取消、预计大小（只能标为估计）；精确大小在编码完成后显示。导出失败保留临时源供重试，成功后可「打开文件夹」。保存对话框覆盖已有文件时遵循明确覆盖确认。
- 放弃：准备态 Esc 直接关闭；录制态 Esc 不默默删除，控制条关闭按钮弹「结束并预览 / 放弃录制 / 继续录制」。预览关闭时未保存内容同样允许返回。系统关机等无法等待的退出尽力停止，不保证异常中断 MP4 可恢复。

一时只允许一个捕获任务。准备中按其它模式快捷键可切换模式并保留有效目标；录制、暂停、收尾中按任一捕获快捷键只唤回现有控制条，不开始新任务。预览未保存时唤回预览。录制控制条获得焦点时 Space 暂停/恢复，不抢占用户在被录程序中的 Space；全局暂停/停止快捷键不列入首版。全屏控制条隐藏时，原启动快捷键负责唤回。

设置中的格式、音频和帧率调整仅影响下次任务；录制过程中不能改变编码器尺寸、设备或音轨。系统声音打开但无法获取设备时，在开始前提示并允许改为无声录制；不能静默输出无声文件。

## 4. 模块与进程边界

采用 WGC + D3D11 + Media Foundation 作为视频主路径；GIF 共用捕获与临时视频，结束后走独立 GIF 编码。录屏最低支持 Windows 10 2004；更早系统保持已有截图能力，入口说明不支持。仍需运行时检测 WGC、GPU 与编码器能力，不只检查版本号。

| 模块（拟新增） | 职责 |
| --- | --- |
| app/hotkeys | 三动作注册、冲突、草稿提交及回滚 |
| recording/process + protocol | 按需 worker、Job Object、带版本的命令/状态协议 |
| recording/session | 单会话状态机、取消代次、统一媒体时钟 |
| recording/target | HWND/HMONITOR/物理像素区域、目标存活与尺寸变更 |
| recording/wgc_source | FramePool、FrameArrived、帧寿命与会话关闭 |
| recording/gpu_pipeline | GPU 裁剪、缩放、BGRA → NV12、纹理池 |
| recording/video_encoder | 硬件 MFT、输入输出背压、H.264 与 MP4 封装 |
| recording/audio_source | WASAPI loopback / 麦克风、重采样、混音、AAC |
| recording/gif_export | 有界解码、调色板量化、帧差优化、GIF 输出 |
| recording/storage | 临时目录、空间检查、提交、取消与遗留清理 |
| ui/recording_* | 选择器、准备条、控制条、预览、导出进度 |

主进程只持有快捷键和小型状态，不传输逐帧像素。使用独立 lumashot_recording_worker.exe，避免托盘进程因静态链接而加载 MF 等新增模块。首次唤起创建 worker；关闭预览/完成后退出并释放 GPU、字体、编解码器缓存。Job Object 绑定父进程生命周期，句柄继承白名单；IPC 使用事件等待或异步管道，不轮询。工作进程无托盘、不读取个人设置，参数由父进程传入。

worker 内 UI 只处理输入与状态；WGC 使用 CreateFreeThreaded，在回调中快速取帧并提交有界工作；D3D11 immediate context 由单一 GPU 执行线程拥有，避免跨线程未同步访问。视频编码与音频按各自事件驱动，磁盘写入和 GIF 转换不在 UI 线程。具体线程数随 MF 实现变化，不能承诺系统总共只有固定线程数。

## 5. 数据路径与占用控制

视频：WGC GPU 纹理 → GPU 裁剪/缩放/转 NV12 → 同适配器 D3D11 感知硬件 MFT → H.264 → MP4。音频：WASAPI → 时间对齐/重采样/混音 → AAC → 同一 MP4。

- 录制优先保持纹理在 GPU，不经现有 CPU Frame::pixels 大数组。这里是避免 CPU 回读，不是承诺 GPU 内完全零拷贝。优先同一适配器捕获、转换和编码；混合显卡需要检测与单独测量。
- 显式启用、枚举并验证硬件编码器，记录实际 MFT、适配器与输入格式。不能把“允许硬件转换”当作硬编成功。驱动拒绝 D3D11 输入时先尝试兼容配置；仍失败在准备界面给出「兼容录制，CPU 占用较高」选项，用户选择后才使用受限软件路径，不静默退化。
- 初始 FramePool 2 帧；自有待处理纹理最多 3 帧，最新帧替换尚未开始处理的旧帧。正在被 GPU/MFT 使用的纹理不能复用；通过完成/释放信号回收。若驱动需要更多池资源，使用显式字节上限并记录，而不是无限增加队列。
- 使用时间戳与帧率门控，不 Sleep 忙等，不为 UI 建立 60 Hz 渲染循环。支持的系统可用捕获更新间隔 API 降低上游频率，运行时检测；旧系统只限制下游处理，不能因此宣称 WGC 本身只捕获 15/30 fps。
- 静态画面无新帧时维持正确时长：用样本持续时间或低频媒体时钟复用已有 GPU 画面；不重新抓桌面。暂停、停止均正确结束末帧时长。持续音频也不能驱动屏幕反复抓取。
- 图形纹理按分辨率计算预算。例如 1080p BGRA 每张约 7.91 MiB，NV12 约 2.97 MiB；帧池、驱动/MFT 私有资源另计。不要承诺整个进程只用这几张纹理的内存。
- 音频使用有界队列（初始上限 250 ms），根据设备时钟和统一时间轴纠偏。超过上限不能悄悄丢弃导致失步，应报告并结束/保存可用录制；音频设备失效给出明确状态。
- 只在任务开始后初始化设备；等待用户框选时不连续捕获桌面。选择器需要背景时只获取一次合成/桌面快照，继续采用后台获取和取消代次机制。
- 录制条采用静态材质或系统合成材质，不逐帧取桌面再模糊；WDA_EXCLUDEFROMCAPTURE 设置并验证。无法可靠排除时区域模式移到选区外，全屏模式隐藏控件，用热键唤回并提示限制。不能仅凭 API 返回成功保证所有路径排除有效。
- 不使用全局高精度定时器常驻提频、强制清理工作集或空转降低界面上显示的占用。

GIF：先以所选帧率和输出大小录制高质量临时 H.264，停止后从磁盘流式解码 → 最多数帧的缓冲 → 调色板量化 → GIF。录制时间长短不能决定内存积累量。临时 H.264 是有损中间格式，需用小字、渐变和鼠标样例验证质量；不称无损。

GIF 编码首版比较 WIC 原生编码和独立编码实现，以文本清晰度、颜色闪烁、文件大小、速度为准决定；WIC 提供 GIF 编码但不能据此假定已有最佳量化和差分优化。可用两遍流式处理生成稳定全局调色板，不把所有帧放内存。15 fps 用 6/7 个百分之一秒的延时分配控制总时长误差，25 fps 为 4；不为每帧固定四舍五入累积漂移。图像差分和重复帧合并需验证 disposal 与循环末尾显示。导出默认低优先级有界线程，预览不播放时不占用解码循环。

## 6. 正确性与故障处理

- 截图继续保持唤起前采样的光标形状/热点/位置；录制捕获实时光标，仅由 WGC 或后备合成其中一种负责，避免双光标。
- 坐标在整个采集链为物理像素，UI 为 DIP，Per-Monitor V2。负坐标、125%/150% 缩放均需验证。H.264 NV12 奇数尺寸通过边缘填充到偶数处理，不能拉伸或少一列内容；元数据/预览明确实际输出大小。
- 首版输出 SDR；HDR 输入若支持 GPU 色调映射则做明确转换并验证，否则提示当前目标暂不支持，不把发灰画面当作正常结果。
- 窗口尺寸变化保持初始输出画布，等比缩放并补边；目标最小化自动暂停并说明，恢复后用户继续；窗口关闭则停止并预览已录部分。显示器断开或设备丢失结束当前会话，尽力封装可用数据，不无限重试。
- 取消使用单调 session generation，撤销回调，停止接收输入，再等在途工作释放资源；陈旧状态消息不能重新打开 UI 或发布文件。不能强行杀线程来释放 GPU 对象。
- 临时文件位于应用专用随机会话目录，保存前检查空间，录制中低频检查。低空间安全停止并说明。正常退出删除本会话未保留临时文件；异常遗留只处理带本应用标记且非活动会话的文件，不扫描或删除用户目录。父进程退出可能使普通 MP4 未完成封装，恢复能力不在首版承诺内。
- 视频先完成临时文件，再提交到用户选择目标；跨卷复制在后台，成功前保留源文件。GIF 导出失败或取消仅删除未完成输出，保留预览源供重试。

## 7. 实现顺序与验收

1. 三动作快捷键、设置页签与协议升级；入口能打开真实准备界面，再对外暴露。不能发布只有快捷键但点击开始无功能的半成品。
2. 单屏区域无声 MP4 完整链路：开始/暂停/恢复/停止/预览/保存、硬编身份与资源测量。
3. 窗口/全屏、系统声音与麦克风、兼容回退、录制条排除。
4. GIF 临时录制、裁剪、量化、循环、导出取消与质量比较。
5. 综合性能及混合 DPI/HDR/显卡兼容验收，补文档及安装包 worker 分发。

功能测试均用自建合成窗口、合成声音、隔离临时配置，禁止使用个人桌面、偏好或剪贴板作为 fixtures。独立测试热键冲突与互换、注册回滚竞争、取消无写入、IPC 错误、子进程退出、状态非法跳转、音画同步、暂停时长、旧代次结果、磁盘失败。编码测试要解码输出比较尺寸、持续时间、内容和音频；GIF 用独立解码器检查帧延时、循环、裁剪与颜色，不仅检查文件存在。

构建运行 build.bat（C++20 /W4 /WX）。实施后必跑 lumashot_capture_test.exe，设置改动覆盖 settings_dialog、tool_preferences、idle_settings_memory，入口改动覆盖 capture_startup/capture_reselect/capture_to_pin，并运行新增录制专项；最终集成运行已注册回归。设计文件与效果图本身不需要编译。

性能矩阵：静态文档、连续滚动、60 fps 合成动画；1080p30/60、4K30；有声/无声、GIF 转换；至少覆盖实际可用的 Intel/AMD/NVIDIA 设备，未覆盖明确标记。记录 OS、GPU、驱动、实际硬/软编码器、冷启动、帧延迟 P50/P95、编码吞吐、丢帧、CPU 平均/P95、GPU 各引擎、私有提交与工作集、GPU 内存、磁盘速率。与同配置上一版/参考路径比较，不能用不同分辨率数据证明更快。

结构性门槛：空闲无 recording worker、捕获事件或录制计时器；预览关闭 5 秒内 worker 退出；队列永不超过上限；连续录制 10 分钟内存不随时长线性增长；10 次开始/取消/结束不累积句柄。性能目标：参考机 1080p30 硬编平均 CPU ≤5%（以总 CPU 为口径）、正常负载有效帧丢失 <1%、音画偏差 ≤80 ms。以上需实测后确认，不能作为所有机器的保证；冷启动和内存先收集基线后设分设备预算。

视觉验收：合成目标的浅/深色、100/125/150/200% DPI、小屏布局、键盘焦点、暂停/失败/导出状态；实际录制文件确认控制条不入画、光标无重影、边缘不裁错。自动化无法覆盖的真实多屏、HDR 和真实全局按键需明确人工验收状态。
